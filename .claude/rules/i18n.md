# Translations

- `src/i18n/translations.js` exports `translations = { en: {…}, es: {…} }` and `LANGS`.
  Both trees have the same shape; a key exists in both or in neither.
- Add a key in **both** languages in the same edit, at the same place in each tree. Spanish is
  written as a native speaker would say it, not word for word (`n/d`, not `n/a`).
- Variables: `{name}` in the string, filled by `t('a.b', { name })`. Counts: `tn('a.b', n)` picks
  `bOne` when `n === 1` and the key exists — add both forms in both languages.
- Top-level groups: `common nav site programs pending landing pricing waitlist auth dash settings tx
  sales crm rep cats inv lv portal ceoComp`. Program copy lives under `programs.<key>`; herd labels under `lv`.
- Never rename or delete a key that a page still reads; grep `t('key` first.
- After any change: `node scripts/i18n_parity.mjs` must print `parity`. It exits 1 and lists the
  missing paths otherwise — fix them before reporting.
- The language preference lives in `localStorage['selric.lang']` and `profiles.locale`; the provider writes both.
